# Лаборатория №2
   Для выполнения лабораторной работы был определен структурный паттерн проектирования **Декоратор** (*Decorator*) .

# Предметная область
   Динамическое добавление дополнительных характеристик персонажу компьютерной игры.

# Описание проблемы
    При создании персонажа возникает необходимость:
    -Настраивать дополнительные характеристики и свойства персонажа поэтапно.
    -Гибко управлять снаряжением и характеристиками без изменения базовых классов.
    -Добавлять новые свойства (например, магические ауры, защитные щиты, усиления) без необходимости менять существующий код.

# Решение
   Использование паттерна **Декоратор**. 
   Декоратор позволяет динамически добавлять новые функциональности или свойства объектам (персонажам), оборачивая их в дополнительные классы-обертки.
    В данном случае:

-**Базовый класс персонажа (AbstractCharacter)** — базовый интерфейс или класс персонажа.  
-**Конкретный персонаж (Pet, Npc, Boss)** — реализует базовые характеристики.  

-**Декоратор (CharacterDecorator)** — абстрактный класс-обертка, реализующий интерфейс персонажа и хранящий ссылку на объект-объект.  
-**Конкретные декораторы (например, ShieldDecorator, MagicAuraDecorator, StrengthDecorator)** — добавляют персонажу новые свойства или характеристики.

-**Клиент (CharacterClient)** — пользовательский интерфейс или логика, которая создает персонажа и динамически оборачивает его в декораторы для расширения.

# Без паттерна
Добавление дополнительных характеристик объекту происходит напрямую, без использования паттерна.

    Минусы:  
    -Трудность добавления новых характеристик без изменения базовых классов.  
    -Высокая связность и сложность расширения.  
    -Меньшая гибкость в управлении свойствами персонажа во время выполнения.
