# Лаборатория №3
   Для выполнения лабораторной работы был определен структурный паттерн проектирования **Посредник** (*Mediator*) .

# Предметная область
   Взаимодействие между персонажами, поиск и обмен предметами.

# Описание проблемы
    -Когда имеется множество взаимосвязаных объектов, связи между которыми сложны и запутаны.
    -Когда необходимо повторно использовать объект, однако повторное использование затруднено в силу сильных связей с другими объектами.

# Решение
   Использование паттерна **Посредник**. 
   представляет такой шаблон проектирования, который обеспечивает взаимодействие множества объектов без необходимости ссылаться друг на друга. Тем самым достигается слабосвязанность взаимодействующих объектов.

-**Базовый класс персонажа (AbstractCharacter)** — базовый интерфейс или класс персонажа.  
-**Конкретный персонаж (Pet, Npc, Boss)** — реализует базовые характеристики.  

-**Декоратор (CharacterDecorator)** — абстрактный класс-обертка, реализующий интерфейс персонажа и хранящий ссылку на объект-объект.  
-**Конкретные декораторы (например, ShieldDecorator, MagicAuraDecorator, StrengthDecorator)** — добавляют персонажу новые свойства или характеристики.

-**Клиент (WindowsProject2)** — пользовательский интерфейс или логика, которая создает персонажа и динамически оборачивает его в декораторы для расширения.

# Без паттерна
Добавление дополнительных характеристик объекту происходит напрямую, без использования паттерна.

    Минусы без паттерна:  
    -Трудность добавления новых характеристик без изменения базовых классов.  
    -Высокая связность и сложность расширения.  
    -Меньшая гибкость в управлении свойствами персонажа во время выполнения.
